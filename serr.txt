### ✅ What Is Technically Good

1. **IDOR protection** — `current_user.projects.find(params[:id])` correctly scopes access
2. **JWT revocation** — JTI Matcher strategy with per-user JTI
3. **Webhook architecture** — Clean separation: Controller → WebhookRequest VO → Processor → Verifier/Checker/Recorder
4. **Contract/interface pattern** — `Contracts::Recordable` and `Contracts::Verifiable` modules
5. **Chain of Responsibility** — Validator chain (`BaseValidator` → `SignatureValidator`) is extensible
6. **Idempotence index** — `[:project_id, :scan_id]` unique composite index on scans
7. **Delivery deduplication** — `delivery_id` unique index on webhook_events
8. **Secret management** — JWT secret requires credentials or env var, no fallback
9. **Secure comparison** — `ActiveSupport::SecurityUtils.secure_compare` for timing-attack resistance
10. **Parameter filtering** — Sensitive params (password, token, secret, key) are filtered from logs

## 2. What Must Be Changed Now

### 2.1 🔴 Fix DuplicateChecker — Logic Is Inverted

**Problem**: The guard clause returns early when `delivery_id` is *blank*, meaning it never checks for duplicates when a delivery ID is present.

**File**: [duplicate_checker.rb](file:///c:/Users/missaoui.DESKTOP-4LNHLUC/RubymineProjects/guardrail-api/app/services/github/duplicate_checker.rb)

**Current (broken)**:
```ruby
def call(delivery_id)
  return unless delivery_id.blank?  # ← BUG: returns when delivery_id IS blank
                                     #   proceeds when it's NOT blank
  if WebhookEvent.exists?(delivery_id: delivery_id)
    raise DuplicateEventError, "Event #{delivery_id} already processed"
  end
end
```

**Fix**:
```ruby
def call(delivery_id)
  return if delivery_id.blank?  # ← Skip check if no delivery_id

  if WebhookEvent.exists?(delivery_id: delivery_id)
    raise DuplicateEventError, "Event #{delivery_id} already processed"
  end
end
```

> [!CAUTION]
> This bug means **every webhook with a valid `delivery_id` passes the duplicate check**, and webhooks **without** a delivery_id (which should be skipped) try to query `WebhookEvent.exists?(delivery_id: nil)`. This completely defeats idempotence.

### 2.2 🔴 Fix Double `request.body.read` in GithubController

**Problem**: `raw_post_body` calls `request.body.rewind` + `request.body.read`, but `params_as_hash` calls `raw_post_body` **again**. After Rails parses params, `request.body` may behave differently. More critically, the body is read once for the `WebhookRequest.raw_body` and once independently for `params_as_hash`, which is wasteful and fragile.

**File**: [github_controller.rb](file:///c:/Users/missaoui.DESKTOP-4LNHLUC/RubymineProjects/guardrail-api/app/controllers/api/v1/webhooks/github_controller.rb)

**Fix**: Read the body once and reuse it:

```ruby
private

def webhook_request
  @webhook_request ||= Github::WebhookRequest.new(
    raw_body:    cached_raw_body,
    signature:   request.headers["X-Hub-Signature-256"],
    event_type:  request.headers["X-GitHub-Event"],
    delivery_id: request.headers["X-GitHub-Delivery"],
    payload:     parsed_payload
  )
end

def cached_raw_body
  @cached_raw_body ||= begin
    request.body.rewind
    request.body.read
  end
end

def parsed_payload
  @parsed_payload ||= begin
    JSON.parse(cached_raw_body)
  rescue JSON::ParserError
    raise Github::InvalidPayloadError, "Invalid JSON payload"
  end
end
```

### 3.3 Normalizer Architecture

Design a strategy pattern so each scanner has its own normalizer:

```
app/services/normalizers/
├── base.rb                  # Abstract interface
├── sonarqube_normalizer.rb  # SonarQube → standard format
├── trivy_normalizer.rb      # Trivy → standard format
└── github_normalizer.rb     # GitHub Actions → standard format
```

```ruby
# app/services/normalizers/base.rb
module Normalizers
  class Base
    def normalize(raw_payload)
      raise NotImplementedError
    end

    # Returns: {
    #   scan_id:, source_type:, commit_sha:, branch:,
    #   author_name:, author_email:, commit_message:,
    #   vulnerabilities: [{ external_id:, title:, severity:, ... }]
    # }
  end
end
```

```ruby
# app/services/normalizers/trivy_normalizer.rb
module Normalizers
  class TrivyNormalizer < Base
    def normalize(raw_payload)
      results = raw_payload.dig("Results") || []
      vulns = results.flat_map do |result|
        (result["Vulnerabilities"] || []).map do |v|
          {
            external_id:   v["VulnerabilityID"],
            title:         v["Title"] || v["VulnerabilityID"],
            severity:      v["Severity"]&.downcase,
            description:   v["Description"],
            file_path:     result["Target"],
            cve_id:        v["VulnerabilityID"],
            cvss_score:    v.dig("CVSS", "nvd", "V3Score"),
            fix_available: v["FixedVersion"].present?,
            fix_version:   v["FixedVersion"],
            raw_data:      v
          }
        end
      end
      { vulnerabilities: vulns, source_type: "trivy" }
    end
  end
end
```

### 3.4 Async Processing with Sidekiq (or Solid Queue)

> [!NOTE]
> Your project already includes `solid_queue` in the Gemfile. You can use it instead of Sidekiq to avoid adding Redis as a dependency. The job interface is identical via Active Job.

```ruby
# app/jobs/process_webhook_job.rb
class ProcessWebhookJob < ApplicationJob
  queue_as :webhooks

  retry_on StandardError, wait: :polynomially_longer, attempts: 3
  discard_on Github::DuplicateEventError

  def perform(webhook_event_id)
    event = WebhookEvent.find(webhook_event_id)
    return if event.status == "processed"

    event.update!(status: "processing")

    # 1. Find or create project by repository
    project = Project.find_by!(github_repo: event.repository)

    # 2. Normalize payload
    normalizer = Normalizers.for(event.source)
    normalized = normalizer.normalize(event.payload)

    # 3. Create scan (idempotent via unique index)
    scan = project.scans.create!(
      scan_id:     normalized[:scan_id] || event.delivery_id,
      source_type: normalized[:source_type],
      commit_sha:  normalized[:commit_sha],
      branch:      normalized[:branch],
      raw_payload: event.payload,
      status:      "processing",
      scanned_at:  Time.current
    )

    # 4. Create vulnerabilities
    normalized[:vulnerabilities].each do |vuln_data|
      scan.vulnerabilities.create!(vuln_data)
    end

    # 5. Update counts + mark complete
    scan.complete!
    event.mark_processed!(scan)

  rescue => e
    event&.mark_failed!(e)
    raise  # Re-raise for retry mechanism
  end
end
```

Update the `EventRecorder` to enqueue the job:
```ruby
def call(event_type:, delivery_id:, repository:, payload:)
  event = WebhookEvent.create!(
    event_type:  event_type,
    delivery_id: delivery_id,
    repository:  repository,
    payload:     payload,
    status:      "pending"
  )
  ProcessWebhookJob.perform_later(event.id)  # ← Async!
  event
end
```

### 5.3 Signature Verification for Generic Scanner

For non-GitHub scanners, use a project-level webhook secret with HMAC-SHA256:

```
X-GuardRail-Signature: sha256=<hmac_hex_digest>
X-GuardRail-Source: trivy
X-GuardRail-Project: missaoui/guardrail-api
X-GuardRail-Delivery: <uuid>
```

```ruby
# app/controllers/api/v1/webhooks/scans_controller.rb
module Api
  module V1
    module Webhooks
      class ScansController < ApplicationController
        skip_before_action :authenticate_user!, only: [:create]

        def create
          project = Project.find_by!(github_repo: request.headers["X-GuardRail-Project"])

          verifier = Github::SignatureVerifier.new(secret: project.webhook_secret)
          verifier.verify!(cached_raw_body, request.headers["X-GuardRail-Signature"])

          # Dedup
          delivery_id = request.headers["X-GuardRail-Delivery"] || Digest::SHA256.hexdigest(cached_raw_body)
          Github::DuplicateChecker.new.call(delivery_id)

          # Record + enqueue
          event = WebhookEvent.create!(
            source:      request.headers["X-GuardRail-Source"] || "unknown",
            event_type:  "scan_result",
            delivery_id: delivery_id,
            repository:  project.github_repo,
            payload:     parsed_payload,
            status:      "pending"
          )
          ProcessWebhookJob.perform_later(event.id)

          head :accepted
        rescue ActiveRecord::RecordNotFound
          render json: { error: "Project not found" }, status: :not_found
        rescue Github::InvalidSignatureError => e
          render json: { error: e.message }, status: :unauthorized
        rescue Github::DuplicateEventError
          head :ok
        end

        private

        def cached_raw_body
          @cached_raw_body ||= begin
            request.body.rewind
            request.body.read
          end
        end

        def parsed_payload
          @parsed_payload ||= JSON.parse(cached_raw_body)
        rescue JSON::ParserError
          raise Github::InvalidPayloadError, "Invalid JSON"
        end
      end
    end
  end
end
```

### 5.4 Idempotence Strategy

| Layer | Mechanism | Protection |
|-------|-----------|------------|
| HTTP | `X-GitHub-Delivery` / `X-GuardRail-Delivery` header | Unique per request |
| Database | `webhook_events.delivery_id` unique index | DB-level dedup |
| Application | `DuplicateChecker` service | App-level check before insert |
| Scan | `scans[:project_id, :scan_id]` composite unique index | Prevents duplicate scan records |
| Vulnerability | `vulnerabilities[:scan_id, :external_id]` composite unique | Prevents duplicate findings |

### 5.5 Handling Duplicate Webhooks Safely

When a duplicate is detected:
- Return `200 OK` (not an error) — tells the sender "we got it, stop retrying"
- Log the duplicate for observability
- Do NOT create a new record

  end

7. `ProcessWebhookJob` + Solid Queue integration

**Why**: This is the core value proposition of GuardRail. Once webhooks are stable and tested, building the scan processing pipeline is the most impactful feature work. The normalizer architecture enables you to add new scanners without changing existing code (Open/Closed Principle).
